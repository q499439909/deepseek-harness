## 开发备注

本节根据已接受的需求提出实现建议，不是当前实现的权威说明。具体包名、记录 schema、API 路由、存储顺序和 UI 布局仍需实现审查。

### 范围与部署

集成可选启用，并通过文档让用户发现。用户自行安装 Data-Juicer 并启动官方 recipe-flow MCP 服务。DSH 通过 Streamable HTTP 连接。首版将两个服务部署在同一台机器，Data-Juicer 监听回环地址，支持一个操作者、上传数据和该操作者可访问的任意本地输入路径，不建立租户隔离。未来多租户支持需要对输入、执行、产物和下载建立经过认证的归属与授权；Workspace 成员关系本身不能提供此授权。

### 用户流程

一个处理任务代表用户要求的一次完整 Data-Juicer 操作，可以跨多个对话轮次。一个会话最多存在一个未解决的处理任务，包括执行状态未知的任务。任务完成、取消或失败后，可以开始下一个任务。多个算子步骤属于同一个 recipe，不分别创建任务。

agent（智能体）先澄清不明确的需求，再编排 recipe。确认前可以检查格式、字段、有界样本和算子参数。完整处理、数据变换和模型/API 调用需要用户确认。方案卡展示输入、算子顺序、重要参数、预期输出和可展开的 YAML，并提供执行、修改和取消操作。修改产生新的 recipe 版本，并使先前确认失效。

执行操作记录对确切版本的确认，并经过程序强制的执行检查。模型不能自行确认 recipe。并发点击必须只能启动一次执行尝试。执行请求包含已校验的输入绑定、recipe、实际生效配置和指定输出位置；自由配置覆盖不能在确认后改变这些内容。原始 MCP 处理工具不能继续作为 agent 的另一条执行路径暴露。算子发现仍通过集成提供。

### 任务状态与中断

建议状态为澄清中、编排中、待确认、执行中、完成、失败、取消和未知。修改回到编排中；提交有效方案进入待确认。执行只能为已确认版本启动一次尝试。支持执行前取消。执行中的可靠取消暂缓，因为断开同步 MCP 调用不能证明服务已经停止处理。

执行完成要求处理成功且输出清单已持久化发布。处理失败记录错误和已有的部分输出信息。发布失败必须区分处理已完成与结果不可用。重启或传输中断后，正在执行的尝试进入未知状态，除非可以核实其结果。重连和重启都不能自动重新提交。未解决的尝试继续阻止下一个任务；重试需要用户核查先前执行后明确操作，且不能在已知先前尝试仍运行时并发启动。

### 持久记录与文件

通过现有存储设施新增一个领域，本部署将其路由到 SQLite。每个任务使用一个聚合记录，包含会话关联、澄清后的需求、输入绑定、不可变 recipe 版本、用户确认、执行尝试、状态、时间、错误、摘要和产物清单。所属服务必须保证单会话活动任务约束及执行尝试的原子启动；具体记录布局仍是设计事项。不能将独立 KV 写入当作多记录事务。

上传输入复制到受管理存储。本地输入保留原位置，不自动复制；应在可行时检测编排与执行之间的变化，并提示重新确认。每个任务和执行尝试分配独立的受管理输出存储，默认不能覆盖输入和历史结果。产物保留该次尝试生成的字节，包括预览或下载所需的引用媒体。清单将产物关联到任务、执行尝试、媒体类型、大小、显示名称和内部存储引用。仅指向可变外部媒体的数据集清单不构成保留的图片输出。

任务状态在重启后保留。输出文件、图片和报告保留到用户显式删除。删除任务不能删除本地源文件。共享附件对象的删除需要检查引用。存储缺失或保留清理失败时，UI 必须准确展示产物不可用。

领域记录拥有运行状态；会话事件记录模型可见的需求、recipe 版本、用户确认、状态摘要和产物引用。浏览器翻页、下载和图片预览不自动进入模型上下文。仅在用户明确要求时，才将选中的行或图片加入模型输入。实现必须定义任务写入已持久化而会话追加失败时的恢复方式，才能承诺一致回放。fork 或导入的会话历史不能复用确认来执行复制的任务。

### Web 结果

每个任务有独立卡片展示方案或当前状态。完成卡展示耗时、可获得的输入/输出数量、提供方给出的阶段统计、警告和完整产物列表。缺失统计显示不可用，不能猜测。首次展示包含数量有界的图片缩略图。现有右侧栏提供图片分页浏览、数据行预览、报告查看和完整产物下载。大数据集保持在模型上下文之外。

复用现有工具卡、附件、侧栏和本地化组件。仅有 UI 插件不足以完成此能力：Host 代码必须校验输出引用、保留字节、将其绑定到任务和会话，并授权预览/下载请求。现有 MCP 图片持久化处理可以复用，但普通数据集下载需要合适的文件服务 API。预览处理必须将生成的 HTML 和其他活动内容视为不可信输出。

### 仓库职责

DSH 拥有完整的数据处理能力，由任务与执行的 Service Definition、Data-Juicer Service Provider 以及模型/UI Consumers 组成。提供方内部使用现有 MCP 传输，而非暴露无限制的处理调用。DSH 还负责输入解析、按版本确认、持久状态、受管理输出、会话投影、产物访问 API、可选组合和 Web 卡片。按角色的独立演化需求拆包，而非每个操作单独拆包；agent loop 不需要新增数据处理分支。

Data-Juicer 负责算子执行和 recipe 语义。集成测试前先按其锁文件核对环境。当前检出的 MCP 辅助函数返回文本路径，并将处理异常捕获为普通字符串；建议上游改进显式错误和结构化输出元数据，而不将 DSH 特定的确认或租户机制复制到 Data-Juicer。必需传输是 Streamable HTTP。stdio 修复不在本设计范围内。结构化输出可用前，提供方必须针对现有结果格式做窄范围测试，并拒绝报告处理错误的结果。

### 验证与实现顺序

先在与锁文件兼容的 Data-Juicer 环境验证真实 HTTP 握手和小型文本 recipe，再实现持久任务及按版本确认，随后接入受管理产物发布与 Web 界面。验收需要真实上传/本地文本处理和图片输出，以及拒绝绕过确认、拒绝重复执行、修改方案使确认失效、重试输出分离、重启恢复、未知状态处理和结果持久化且数据集字节不进入模型请求。能力、生命周期、API 和 UI 需要针对性测试；模型可见行为需要无密钥的会话录制用例。GUI 改动按仓库政策需要真实服务/模型流程录制的 GIF 和产品/设计审查。

### 剩余工程事项

记录 schema、输入身份检查、实际生效配置校验、媒体数据集输出收集、跨存储恢复、统计收集、文件服务 API 和提供方错误映射需要实现调查。真正的多租户授权、远程数据传输、持久远端作业核对和执行中取消属于后续产品能力。上传和预览预算需要可配置，具体值依据处理与浏览器实测确定。
