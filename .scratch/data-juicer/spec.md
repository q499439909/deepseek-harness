# DSH Data-Juicer：经用户确认的数据处理任务与持久化 Web 结果

## Problem Statement

用户希望通过 DSH 的自然语言对话使用 Data-Juicer 的数据处理能力，处理上传数据或本机已有数据。用户需要在目标不明确时先澄清需求，再检查 agent 编排的算子、参数和预期输出，明确确认后才执行。用户还需要在 DSH Web UI 中查看每次处理的整体结果、处理后的图片，并预览或下载完整数据集。

直接连接官方 Data-Juicer MCP 只能解决算子发现和执行的一部分问题。现有路径字符串结果不能自动形成持久任务、方案确认、结果统计和 Web 产物展示；无约束地暴露执行工具也不能保证用户确认实际执行的方案。单个对话轮次不能覆盖澄清、修改和确认的完整流程。

## Solution

提供可选的 DSH 数据处理集成。用户自行安装并启动 Data-Juicer 官方 recipe-flow MCP，DSH 通过 Streamable HTTP 连接。首版在同一台机器上运行两个服务，Data-Juicer 只监听回环地址，支持单用户、数据上传和操作者有权限访问的任意本地输入路径。

一个处理任务承载一次完整的用户处理目标，可以跨多个会话轮次。同一会话同时只推进一个未结束任务。用户提出需求后，agent 澄清、检查数据和编排 recipe；Web 方案卡展示输入、步骤、参数和预期输出。用户通过执行按钮确认具体版本，DSH 检查确认后才调用 Data-Juicer。任务完成后，结果卡展示统计、警告和产物，图片可直接查看，数据集可分页预览和完整下载。

任务与输出在重启后保留。任务记录和文件元数据进入数据库，大文件保存在受管理文件存储中。模型只接收必要的需求、方案、状态和结果摘要；完整数据集及纯 UI 浏览行为不自动进入模型上下文。未来可扩展多租户，但首版不提供租户隔离保证。

## User Stories

1. 作为 DSH 用户，我希望发现可选 Data-Juicer 集成，以便了解可用的数据处理能力。
2. 作为 DSH 用户，我希望默认使用 DSH 时不需要安装 Data-Juicer，以便按需要承担部署成本。
3. 作为操作者，我希望配置官方 recipe-flow HTTP 服务地址，以便复用官方算子执行能力。
4. 作为操作者，我希望首次部署使用同机回环 HTTP，以便直接处理本地数据。
5. 作为用户，我希望上传数据文件，以便处理尚未存在于 DSH 工作目录的数据。
6. 作为用户，我希望选择任意有权限读取的本地数据集路径，以便复用已有数据而不强制复制原始数据。
7. 作为用户，我希望用自然语言描述处理目标，以便不必先学习全部算子和 YAML 参数。
8. 作为用户，我希望需求不清晰时 agent 先追问，以便减少错误编排。
9. 作为用户，我希望 agent 在确认前检查数据格式、字段和少量样本，以便生成适合输入数据的方案。
10. 作为用户，我希望确认前不发生完整数据变换或模型/API 调用，以便保留对处理行为和费用的控制。
11. 作为用户，我希望一个完整处理目标只有一个任务，以便多算子流水线不会被拆成混乱的独立任务。
12. 作为用户，我希望一个任务可以跨多轮对话，以便完成澄清和方案修改。
13. 作为用户，我希望当前任务结束后再开始下一个，以便理解会话中各个结果的归属。
14. 作为用户，我希望查看输入、算子顺序、关键参数和预期输出，以便判断方案是否符合目标。
15. 作为熟悉 Data-Juicer 的用户，我希望展开完整 YAML，以便检查详细编排。
16. 作为用户，我希望用自然语言提出方案修改，以便迭代处理规则。
17. 作为用户，我希望修改方案后原确认失效，以便避免旧确认授权新的处理行为。
18. 作为用户，我希望通过执行按钮确认当前版本，以便明确控制执行开始时间。
19. 作为用户，我希望程序拒绝未经确认或版本不匹配的执行，以便 agent 不能绕过确认。
20. 作为用户，我希望重复点击执行不会产生重复处理，以便避免重复资源消耗。
21. 作为用户，我希望执行前可以取消任务，以便放弃不再需要的方案。
22. 作为用户，我希望每次执行有独立输出位置，以便输入和历史结果不被覆盖。
23. 作为用户，我希望失败后可以明确发起重试，以便重试结果与前次结果区分。
24. 作为用户，我希望看到处理状态、耗时、可获得的输入输出数量、统计和警告，以便了解整体处理结果。
25. 作为用户，我希望缺失统计被明确标示，以便不把估算或空值误认为实测数据。
26. 作为用户，我希望直接看到处理后图片的缩略图，以便快速检查效果。
27. 作为用户，我希望分页浏览所有输出图片，以便大批量图片不会一次加载到浏览器。
28. 作为用户，我希望分页预览数据行和查看分析报告，以便检查输出质量。
29. 作为用户，我希望下载完整数据产物，以便用于后续训练、分析或归档。
30. 作为用户，我希望 Web 浏览和下载不自动把完整数据发给模型，以便控制上下文和数据访问。
31. 作为用户，我希望明确选择样本或图片交给模型分析，以便获得有针对性的解释。
32. 作为用户，我希望刷新页面或重启 DSH 后仍看到任务和结果，以便恢复工作。
33. 作为用户，我希望历史图片和数据产物保留当次输出，以便源路径后来变化时仍能查看原结果。
34. 作为用户，我希望连接中断时看到执行状态未知，以便不会把断线误认为处理失败或成功。
35. 作为用户，我希望重启或重连不自动重试，以便服务端仍在处理时不会重复提交。
36. 作为用户，我希望处理失败与结果发布失败得到区分，以便知道应该重跑处理还是恢复输出。
37. 作为用户，我希望显式删除保留的结果且不删除本地输入，以便清理存储时保留源数据。
38. 作为用户，我希望丢失的产物显示不可用且有明确错误，以便不会点击无效预览或下载。
39. 作为维护者，我希望集成复用已有 MCP、存储、附件和 Web 组件，以便保持 DSH 的插件架构。
40. 作为未来多租户部署者，我希望任务、输入和产物拥有明确关联，以便后续在实际授权层加入租户隔离。

## Implementation Decisions

- 统一用语：处理任务代表完整处理目标；recipe 版本是不可变方案；确认授权一个具体版本；执行尝试是一次实际提交；产物是当次尝试保留下来的文件、图片或报告。处理任务不同于会话轮次，也不等同于现有进程内后台任务。
- 建立一个完整的数据处理能力入口，由 Service Definition 管理任务、方案、确认和执行，Data-Juicer Service Provider 执行处理，模型工具和 Web/API Consumers 使用该能力。包按独立演化职责拆分，复用既有能力，不修改 agent loop 来加入特殊处理流程。
- 复用官方 recipe-flow，使用 Streamable HTTP。首版用户自行安装依赖并启动服务；DSH 不自动下载 Python、Data-Juicer 或模型权重，不默认启用集成。
- Provider 私下连接 MCP。算子发现和安全的有界检查可以提供给 agent；原始处理/分析执行工具不能成为绕过 DSH 确认检查的路径。
- 输入使用上传数据引用或本地路径绑定。上传数据进入受管理存储，本地数据不自动复制。首版允许操作者可访问的任意本地输入路径；Workspace 只用于组织，不能当作租户授权依据。
- 编排前允许格式、字段、少量样本和参数检查；实际数据变换、全量处理和模型/API 调用必须在确认后执行。检查和预览预算由部署配置控制。
- 每个 recipe 版本固定输入绑定、算子顺序、参数、实际生效配置和输出安排。展示方案以易读步骤为主，完整 YAML 可展开。修改产生新版本并撤销旧确认。
- 用户执行按钮通过受认证的 API 确认版本并请求执行。程序校验任务、会话、当前版本、确认记录和执行状态；模型无法生成有效的人类确认。重复点击、过期页面和并发请求只能启动一次尝试。
- 实际配置不能通过 extra_config 等字段在确认后覆盖输入、算子或输出位置。执行前发现可识别的输入变化时，要求重新审阅确认；检测策略必须明确其能力限制，不能声称任意路径输入已完整冻结。
- 同一会话最多有一个未结束任务。状态包含澄清中、编排中、待确认、执行中、完成、失败、取消和未知。方案可以往返修改；未知执行继续占用任务，直到核实结束，不能直接并发提交下一次处理。
- 首版只支持执行前取消。同步 MCP 请求断开不保证服务端停止。重启或失联后无法确认结果时记录未知，不自动重提；用户核查先前执行后才可明确重试，且不能与已知仍运行的尝试重叠。
- 使用现有领域存储定义任务领域，并在本部署路由到 SQLite。记录至少包含任务和会话关联、需求、输入、方案版本、确认、尝试、状态、时间、错误、结果摘要和产物清单。任务 admission 与同会话单活动任务约束由服务原子地保证；不把独立 KV 写入当作多记录事务。
- 数据库保存元数据，文件存储保存大文件。任务和执行尝试使用独立输出位置，默认不覆盖输入、其他任务或先前尝试。图片数据集中的引用媒体也必须保留，不能只保存指向可变原图的清单。
- 产物清单关联任务与尝试，并记录不透明产物 ID、类型、大小、显示名和内部存储引用。客户端以任务/产物引用预览或下载，服务端验证归属，不把浏览器提供的任意路径直接用于下载接口。
- 结果保留到显式删除。删除不影响原始本地输入；共享对象按引用清理。数据删除与状态更新需要可恢复，文件缺失和部分清理失败应在 UI 中准确显示。
- 领域记录拥有运行状态；模型可见需求、方案、确认、状态和产物引用通过会话日志重建。文件内容和浏览器分页状态不自动进入模型请求。任务存储与会话追加之间的失败必须有恢复规则；会话 fork/导入不能复用历史确认执行任务。
- 处理成功且产物清单已持久化发布后才能展示完整完成状态。处理失败记录错误和部分产物；发布失败明确表示处理结果尚未可用。不能仅凭一个文本输出路径宣称成功。
- Web 插件在会话中按任务展示方案、状态和结果卡。完成结果包含耗时、可获得的行数或样本数、统计、警告和产物列表；缺失指标显示不可用。图片先显示有界缩略图，右侧栏分页浏览图片、预览数据、查看报告和下载完整产物。
- 复用现有工具卡、附件、侧栏、预览和 locale 组件。Web 从原始会话事件、工具结果及持久元数据派生展示。Host 负责输出校验、保存和文件服务；普通文件下载需补足现有图片附件服务不能覆盖的接口。HTML 等活动输出使用现有隔离预览原则。
- Data-Juicer 仍负责算子及 recipe 语义。首先修正本地环境与锁文件的一致性并验证真实 HTTP 服务。Provider 处理官方文本结果并拒绝被包装为普通字符串的处理错误；上游结构化结果和错误改进可以单独贡献，不将 DSH 确认或租户规则写入 Data-Juicer。
- 所有部署可调项进入可校验配置，包括服务地址、调用超时、上传和预览预算、保留数据位置。具体包名、存储 schema、API 字段和媒体收集实现由工程调查确定。

## Testing Decisions

- 用户已确认测试入口：以单一数据处理能力为最高入口，通过真实工具/API 验证输入、编排、确认、HTTP 执行、持久结果和 Web 预览/下载，复用已有 MCP、存储、附件和 UI 测试。不能为每个算子创造独立架构入口。
- 好的测试验证外部行为、可见结果和执行次数，不锁定内部 helper、调用顺序或私有类布局。测试用小型真实数据、临时目录和本地 HTTP 端点，避免共享固定端口、共享进程状态及依赖长等待。
- 对任务服务测试跨轮次修改、方案版本失效、未经确认拒绝、过期确认拒绝、有效确认执行一次、并发点击去重、单会话任务约束和执行前取消。测试同一输入条件下的允许路径和拒绝路径。
- 对 Data-Juicer Provider 使用真实 recipe-flow HTTP 握手和实际执行，覆盖上传数据、本地数据和图片处理，核对输出字节/记录及清单归属。官方服务异常不能显示为成功。不要仅以 CLI help 或 mock 握手代替真实服务测试。
- 对持久化测试重启后方案、确认、尝试和结果恢复；处理中重启或失联产生未知且不重新提交；确认落盘失败、执行 admission 失败、任务已保存而会话追加失败均须有可观察的恢复结果。
- 对输出发布测试不同任务/尝试互不覆盖、原输入保持、引用图片收集、处理成功但发布失败、部分输出、缺失文件和删除失败。历史产物展示当次输出，不随原始路径变动。
- 对 API 测试任务/会话归属、伪造产物引用、未经许可访问、完整下载和分页预览；UI 浏览下载不能改变模型输入。测试会话 fork/导入不继承可执行的确认。
- 对模型上下文测试必要的方案、确认与状态可以从日志重建，完整数据集和未选择的图片不进入请求；明确选择的样本可进入。覆盖 native 和 PTC 的实际调用路径，按新会话事件要求更新两种语言 SDK 的预期输出。
- 对 Web 测试方案修改、Execute/Modify/Cancel 操作、状态恢复、统计缺失、图片分页、数据预览、下载以及保留内容时的错误/重试。复用工具卡、交付物、文件预览和附件授权的现有测试模式。
- 使用 keyless 录制会话覆盖非平凡模型/用户可见行为；真实模型验收独立于可重复的无密钥测试。按照仓库要求录制真实服务器与模型流程的 GUI GIF，并完成产品/设计审查。
- 参考现有 MCP wire e2e、领域存储持久化、Session 附件授权、交付物卡和右侧文档预览测试。仅运行覆盖当前改动的必要检查，CI 负责完整覆盖和平台矩阵。
- 增量验收顺序：真实 HTTP 文本处理；任务持久化与确认；结果发布及图片收集；Web 预览/下载；重启和失败恢复。每一阶段都保持未经用户确认不能处理的规则。

## Out of Scope

- 首版多租户身份、租户 ACL、存储与算力隔离及租户配额。
- 公网裸露部署；远端数据上传/传输协议及跨机器共享存储配置。
- DSH 自动安装 Data-Juicer、Python、GPU 库、全部可选算子依赖或模型权重。
- 从零实现新的 Data-Juicer MCP，或默认暴露全部 granular-ops 工具。
- stdio 修复或以 stdio 作为本功能的必需传输。
- 可靠的执行中取消、远端持久作业队列、细粒度实时进度和断线自动重试。
- 自动复制完整本地输入数据集，或承诺本地输入路径等于不可变数据快照。
- 自动上传完整数据集到模型上下文，或将普通浏览行为自动转成模型消息。
- 增加独立侧栏框架或为每个算子构建定制 UI。
- 修改 agent loop 以实现数据处理专属分支。

## Further Notes

这份规格综合已确认的设计决策；数据处理任务的产品流程、传输选择和测试入口均已讨论。实现前无需重新开展产品访谈，但存储一致性、输入变化识别、媒体引用收集及 API 字段仍需按代码调查解决。

当前本地安装曾解析到不兼容现有 FastMCP 实现的 MCP 版本。集成验收必须使用与 Data-Juicer 锁文件一致的环境，完成真实服务握手；先前 CLI help 成功不能作为服务可用证据。

真实多租户属于后续工程：必须在输入、执行、产物和文件服务层加入授权，不能只给目录加一个前缀，也不能将 DSH Workspace 或同进程注册 scope 当作安全隔离。

任务管理使用本地 Markdown，配置见 docs/agents/issue-tracker.md。此文件是 .scratch/data-juicer/spec.md；十个实现任务分别保存在 .scratch/data-juicer/issues/，使用默认分流状态并按依赖推进。发布仅写入本地文件，不创建远端 Issue，也不改动仓库标签。
