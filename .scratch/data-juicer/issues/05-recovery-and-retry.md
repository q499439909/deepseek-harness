# 05: 重启恢复、未知状态核查与重试

**What to build:** 用户在服务断线或 DSH 重启后恢复处理任务，区分确定失败与执行状态未知，核查先前尝试并显式重试；历史结果保持可用，任务不会被静默重复执行。

**Blocked by:** 03 — 确认方案并完成首次文本处理

**Status:** ready-for-agent

- [ ] 恢复需求、方案、确认、执行尝试、摘要和产物；持久确认记录的存在不触发自动执行或重新提交。
- [ ] 无法验证结果的进行中尝试显示未知，HTTP 断开不被当作服务端停止、确定失败或完成。
- [ ] 提供用户可理解的核查与明确重试流程；未知尝试未解决前继续阻止下一任务，不能与已知仍运行的尝试重叠。
- [ ] 保持已确认版本不变的显式重试创建新的尝试和独立输出；方案变化要求确认新版本。
- [ ] 恢复处理成功但产物发布失败的情形，避免为恢复输出不必要地重新运行处理；部分输出不得误呈现为完整结果。
- [ ] 领域存储成功而会话追加失败、确认保存失败及尝试启动失败有明确且可测试的恢复结果，不能假定跨存储事务。
- [ ] 会话 fork/导入只展示历史信息，不继承可用于执行的确认；源会话的未知任务不会被复制为自动执行。
- [ ] 使用小型真实任务与故障注入验证恢复界面和实际提交次数，不依靠长睡眠；补 keyless 恢复场景、必要 SDK 预期输出和真实 GUI GIF。
