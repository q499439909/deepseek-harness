# 03: 确认方案并完成首次文本处理

**What to build:** 用户确认方案卡的具体版本后，DSH 真实调用 Data-Juicer 处理一个小型本地文本数据集，保留输出、产物清单和结果摘要，并在任务卡展示成功或明确失败。

**Blocked by:** 02 — 创建任务、澄清需求并审阅方案

**Status:** ready-for-agent

- [ ] 执行按钮通过受认证 API 确认当前 recipe 版本，服务验证任务、会话、版本和状态；模型不能创建有效的人类确认。
- [ ] 未确认、过期确认、修改后确认失效、版本不匹配或第二活动任务均拒绝执行；并发点击只能启动一次执行尝试。
- [ ] 生效配置与展示并确认的版本一致；extra_config 等覆盖不能在确认后改变输入、算子或输出安排，可识别的输入变化要求重新确认。
- [ ] 通过官方 recipe-flow HTTP 执行真实文本 recipe；官方普通文本中的异常被视为失败，不能仅因返回路径字符串而报成功。
- [ ] 每个任务及尝试有独立受管理输出，默认不覆盖输入或历史产物；保存输出字节和带任务/尝试归属的产物清单。
- [ ] 数据库保存确认、尝试、状态、时间、错误和摘要，模型可见结果写入会话日志；完整数据集不进入模型请求。
- [ ] 只有处理成功且产物清单持久发布后才显示完成；明确区分处理失败、部分输出和处理成功但结果发布失败。
- [ ] 本票即保证断线/重启不自动重提、未知尝试不能并发启动另一处理；执行中不提供声称已停止服务端的取消操作。
- [ ] 用真实 HTTP 文本处理和可重复失败注入验证输出、确认绕过拒绝、并发去重、发布失败与未知状态；补 keyless 会话、两种 SDK 受影响预期输出和真实 GUI GIF。
